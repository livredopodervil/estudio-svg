# RD Studio 5 / GIL 0.1.2 — organização e autoria

Autoria do sistema: Rogério Duarte. Fase experimental. O servidor administrativo RD Studio é a autoridade de instalação, prévia e edição do site. O Estúdio SVG e o GIL mantêm seus serviços e formatos independentes. Não mover nem fundir os repositórios sem plano aprovado.

## Unidade arquivística proposta e primeiro contrato

Uma composição publicada pela nova versão é uma unidade identificável por `projetos/<id>/`. O `component.json` v1 registra ID, título, descrição, produtor, linguagem e os caminhos, papéis, tamanhos e SHA-256 dos artefatos. `projeto.gil.txt` é a fonte; `player.html` e `index.html` são derivados; `assets/video.mp4` pode ser um vídeo anexado de outra origem (sua correspondência semântica à fonte não é garantida). O manifesto não contém seu próprio hash; o envelope RD Patch inclui esse hash. Não armazenar segredos, caminhos locais, dados clínicos ou credenciais nesse diretório publicável. Pacotes antigos continuam válidos. `catalog/projects` permanece a autoridade do catálogo do site; sua inscrição é uma etapa explícita, não automática. Não há ainda biblioteca global nem indexação de todos os recursos. A pasta `gil/examples/` contém programas e catálogo JSON de exemplos; a primeira UI tem uma lista de exemplos fixa. Future: registro de providers e dependências, identidade persistente e versões de recursos, manifests cross-project, histórico de edição e catálogo de assets integrados sem duplicação de autoridade.

## Produzir

1. Inicie `python tools/launch.py --site DIRETORIO_VERIFICADO --video DIRETORIO_VERIFICADO` na raiz deste kit. Abra 8875. Visão geral → Editor de vídeo (8784), GIL (8791), Editor de páginas. A aba Multimídia também apresenta os acessos. Use 8876 para prévia; não execute conteúdo exportado na origem administrativa.
2. GIL → escolha Máquina cinética e Carregar exemplo. Edite fonte e console; salve `.gil` antes de trocar. O programa usa 108 objetos, 20 faixas, 12 cues, 24 s. `gil/examples/kinetic.gil` e `.md` são a fonte e a descrição. O renderizador de projeção SVG (não WebGL nativo) usa a mesma timeline usada na exportação. Não confundir simulação conceitual com física.
3. Para gerar MP4, `python gil/tools/export_mp4.py gil/examples/kinetic.gil /CAMINHO/NOVO.mp4 --fps 24 --long-side 960`. Requisitos: Node, FFmpeg/ffprobe com libx264/AAC, rasterizador `rsvg-convert` ou CairoSVG. A ferramenta recusa ausência; não instala dependências. Ajuste `--duration` para trecho inicial, `--silent` para sem som, `--long-side` menor para reduzir resolução. Exporta até 120 s; usa diretório temporário, saída nova; prévia e exportação usam o mesmo planejamento de cues, mas a síntese PCM offline pode diferir timbristicamente do Web Audio. Ainda não mistura arquivos de áudio, música, narração gravada ou clipes externos. Use Estúdio SVG para esses fluxos. Estudaremos integração pelo contrato público, sem outro motor de domínio.
4. No gerador de páginas GIL, inclua o MP4 em arquivo escolhido, título, ID novo e texto. Ou use `node gil/tools/build_page.mjs FONTE DIR ID TITULO TEXTO.md [VIDEO.mp4]`. O resultado não escreve no site. Use Pacotes IA → Examinar → Aplicar → Vistoria. Limites RD Patch: 8 MiB por arquivo, 12 MiB pacote. A página de máquina fornecida em `demo/` já contém o vídeo de 24 s/12 fps/640x360, fonte, player, manifesto e HTML. Instale local ou publique em worktree separado, não ambos no mesmo destino sem verificar conflitos.
5. Para componentes novos, escolha IDs diferentes; revisão do mesmo ID ainda requer patch replace com os hashes atuais, não force. Cadastre o projeto no Catálogo se desejar link no portfólio. Não há editor visual de blocos arbitrários da página nesta fase.

## Publicação segregada e bot YouTube

A `main` do site contém alterações automáticas de `data/social-latest.json`; nunca copiar a main histórica nem sobrescrever esse arquivo. `tools/prepare_publication.py --prepare-demo` cria novo worktree da main remota E adiciona apenas `projetos/gil-maquina-cinetica/`. Se avançar entre revisão e publicação, prepare de novo e use novo worktree. Sem force push. Não reutilizar os worktrees preparados na 0.1.1. A fonte integrada deve partir do HEAD audiovisual V3.6 limpo, já publicado em release/v3-alpha4-rc1; se o remoto ainda for 309535f, o script rejeita. Revisar licenças e origem dos módulos antes de `--confirm-rights`. Preservar histórico Git e créditos.

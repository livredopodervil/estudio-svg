Instalar e publicar

  1. ProduzirCrie a composição e renderize MP4 no GIL ou no Estúdio SVG.
  2. Gerar páginaEscolha título, ID e texto no gerador GIL; baixe o arquivo .rdpatch.zip.
  3. ExaminarEm Pacotes IA, confira o conteúdo e aplique no worktree correto.
  4. Vistoriar e publicarUse a prévia isolada, os testes e o assistente Git já existentes. Nenhum push automático.

O GIL não recebe o token administrativo. As portas 8791 e 8784 são fixadas pelo inicializador experimental.

Organização dos componentes

Fonte GIL → composição validada → player HTML e vídeo MP4 → pacote RD Patch → página e catálogo do site. A fonte do projeto deve acompanhar os derivados. Consulte README.md e docs/WORKSPACE.md na instalação.

3 · Parâmetros do navegador 3D

CONTROLES EXPERIMENTAIS

Parâmetros declarativos para câmera, navegação e animação. Na primeira aplicação o Studio instala um pequeno adaptador no motor conhecido, com backup. Nas próximas, modifica somente config/spatial.json. Não incorpora o runtime do SpatialSeed.

4 · Publicação assistida e recuperação

REVERSÍVEL

Etapas: salvar → executar Vistoria → revisar arquivos → criar commit → publicar. O assistente verifica se o GitHub avançou e cria uma tag remota de backup antes do push.

Reverter uma publicação

Cria um novo commit restaurando um snapshot anterior. Exige worktree limpo, alinhado com o GitHub e confirmação explícita. Não usa force push.

MÓDULOS REMOVÍVEIS · VERSÕES AUDITÁVEIS

Pacotes de atualização.

Atualize seções específicas sem trocar a árvore do site. Cada pacote declara seus arquivos, hashes, versão e operação reversível.

Pacotes em Downloads

SEM UPLOAD

Salve um arquivo *.rdpatch.zip na pasta Downloads do Android. O Studio encontra automaticamente os pacotes e verifica o conteúdo sem executar scripts contidos neles.

Selecione um pacote para ver as mudanças.

Se os arquivos foram alterados desde a versão prevista, a aplicação será bloqueada, sem sobrescrever trabalho existente.

Pacotes instalados

RECUPERÁVEL

A remoção restaura apenas os arquivos afetados usando backups externos ao Git. Se o patch já estiver no GitHub, publique a reversão como novo commit.

Depois de aplicar

Abra a Prévia, execute Vistoria e use Organizar e publicar para revisar um commit só com os arquivos modificados. O gerenciador não envia nada automaticamente ao GitHub.
